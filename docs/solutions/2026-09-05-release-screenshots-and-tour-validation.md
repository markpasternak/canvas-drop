# Rendered views, complete tours

`networkidle` can occur before a lazy dashboard route renders. The old docs capture saved two images containing only the app shell. Wait for the main h1 and loaded fonts, then the intended empty-state content or creation field before docs capture. A heading alone can appear while list data is still loading. Inspect every image: a successful screenshot command proves only that bytes were written.

The capture scripts now fail when a requested view is absent or a capture fails, and always close Chromium. The animated WebP builder requires all eleven 1440 by 900 frames and rejects a missing or differently sized frame before writing the tour. The skin comparison uses light mode, real demo covers, checks the settings response, and restores the previous skin in a finally block. Verify the result's page count, frame dimensions, delay and loop metadata: eleven frames, 3000ms each, infinite loop.

The final pass also exposed clipped content in the shared canvas card: a fixed 3:2 aspect ratio was shorter than its title, badges and description at four columns. Let content determine height with a 16rem minimum and bound the wrapping badge group to the card width. Keep the Gallery's cover, overlay, actions and single navigation target. In the browser, card scrollHeight now equals clientHeight at desktop and phone sizes. The Pricing Calculator example also stacks its form and result in a narrow editor preview.

For this round, the eleven tour views, three empty documentation views, two-skin comparison and animation were regenerated from the completed local UI. All content is local example data, including synthetic usage; no production content or credentials appear in the captures. The documentation now embeds its three images, rather than leaving unused files in assets.

Use `CANVAS_DROP_DASHBOARD_URL` to target the correct isolated dev instance. Capture populated marketing data separately from an empty database started with `CANVAS_DROP_DEV_SEED=0`. Never reset production or a shared local database to get empty screenshots. The demo-app seed creates canvases and is not a refresh command for an already populated database.

The independent Claude Opus 5 review prompted content-specific readiness gates and stronger cleanup diagnostics. Skin capture retains both the capture and restore errors in an AggregateError, closes Chromium even on preflight failures, and clears its temporary override if the original skin came from environment/default. Six regression cases cover success, no original override, capture plus restore failure, restore-only failure, unreadable settings and page-creation failure. The local review and validation passes ran sequentially under the repository mapping.

Checks: visual inspection of every frame and both skins; 320/390px and desktop card fit; missing-frame and wrong-dimension failures in a separate fixture; full lint/typecheck and dual-dialect/dashboard tests, docs generation and build. Browser automation used the local capture scripts and an isolated agent-browser session when the connected desktop browser became unavailable.
